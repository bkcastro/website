Lyd.io

Tech: Three.js | WebXR | Node.js


Lyd.io is a spatial video social media platform utilizing 360° and 180° stereoscopic video. As a Software Engineer and UX/UI Designer, I designed and implemented the client application for the Meta Quest 3 and Apple Vision Pro. Additionally, I optimized the feed system's display algorithm and extended cross-platform compatibility across major XR devices and browsers, including Safari, Chrome, and Firefox.

UX

__1 image of hand tracking and 1 of VR Controller__

Hand tracking or VR controllers

I designed and implemented an input-agnostic system allowing users to interact with the application via hand tracking or traditional VR controllers. This ensures the application remains future-proof and compatible with contemporary, controller-free spatial devices like the Apple Vision Pro.

Gestures

__sample gif of the gesture system__

  • Flick up to move up the feed.
  • Flick down to move down the feed.
  • Flick forward to open the media UI.
  • Flick backwards to close the media UI.
  • Flick to the right to enter the content creators spatial environment.
  • Flick to the left to enter the users spatial environment.

These intuitive gestures allow users to navigate content instantly. Extensive user testing and iterative development were required to fine-tune the gesture thresholds and seamlessly integrate them into the application.


Architectural robustness was a core philosophy for this spatial application. Unlike traditional 2D interfaces, 3D spatial environments present infinite layout and interaction possibilities. Because user preferences vary wildly in spatial computing, our system was built to be highly modular, allowing the team to iterate rapidly without architectural limitations.


Note: The system includes a UI-based alternative that completely circumvents gestures, catering to users who prefer traditional menus.

UI

__3-4 sample images of the UI__

Content + media controls

The core of any social media application is its content delivery. Through rigorous trial and error, I designed an elegant user interface that allows intuitive spatial interaction. To minimize cognitive load, I established a clear separation of intent across components: the bottom grid pertains strictly to system-wide interactions (exiting, changing environments, searching), keeping the main viewing space uncluttered.

Environments

__3 pictures of each environment__


The UI dynamically adapts across three distinct virtual environments:

  • The User Environment: Access to personal data and saved content.
  • The Feed Environment: Immersive streaming of stereoscopic videos
  • The Creator Environment: Dedicated space for content porfolio

By deliberately separating content from environmental space, the UI architecture remains clean and context-aware.

Internal Developer Tools

To streamline design, implementation, and integration, I independently developed a suite of internal tools. This proactive initiative saved the engineering team countless hours of debugging and deployment time.

Spatial terminal

__picture of the spatial terminal__


Debugging inside a WebXR session is notoriously difficult because standard browser developer tools (like Chrome DevTools) are inaccessible while wearing a headset. This tool overlays a virtual console directly into the spatial environment, allowing developers to view console.log messages and errors in real-time during live testing.

Space divisor

__picture of the spaces divisor__


Spatial UX layout relies on relative distance from the user, traditionally categorized into three zones:

  • Intimate Space: within 1 foot.
  • Personal Space: 1.5 to 4 feet
  • Social Space: 4 feet or more.

To visually map these boundaries, I built a tool using color-coded geometric zones. This allowed our design team to holistically evaluate UI placement and maximize ergonomic comfort.

Headset-free simulator

__picture of the VR UI rendered on the desktop__


Constantly donning and removing a VR headset to test minor code changes introduces massive friction into the development cycle. To solve this, I built a desktop simulator that renders the 3D spatial UI directly in a standard 2D browser window. It maps mouse clicks to spatial gaze and hand-tracking triggers, and includes a panning feature to simulate different head perspectives, drastically accelerating our UI testing cycles.
